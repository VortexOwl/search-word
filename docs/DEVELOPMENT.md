# Search Word

Техническая документация сервиса поиска русских существительных по набору фильтров.
Сервис перебирает слова из локального словаря `src/data/russian_nouns.txt` и возвращает слова, соответствующие следующим фильтрам:

- длина слова;
- обязательные символы;
- запрещённые символы;
- фиксированные символы на определённых позициях;
- запрещённые символы на определённых позициях.

Результат может быть:

- отображён в веб-интерфейсе;
- возвращён в виде обычного текста;
- сохранён в файл отчёта;
- выведен в консоль.

## 5. Модель фильтра

Основная модель параметров — `LetterFilterModel` из `src/config.py`.

| Поле                   | Тип                | Значение по умолчанию | Описание                                                |
| -------------------------- | --------------------- | ---------------------------------------- | --------------------------------------------------------------- |
| `word_length`           | `int`              | `5`                                   | Длина искомого слова                          |
| `letters_excluded`      | `str`              | `лт`                                | Символы, которых нет в слове             |
| `letters_included`      | `str`              | `аня`                              | Символы, которые есть в слове           |
| `letters_excluded_pos`  | `list[str]`        | `["а", "", "б", "", ""]`            | Исключённые символы по позициям     |
| `letters_fixed_pos`     | `list[str] \| str`  | `+а+н+`                             | Фиксированные символы по позициям |
| `is_save_file`          | `bool`             | `True`                                | Сохранять ли результат в файл          |
| `is_output_terminal`     | `bool`             | `False`                               | Выводить ли результат в консоль      |

Символ `+` в строковом `letters_fixed_pos` означает свободную позицию.

Пример:

```text
+а+н+
```

Ограничение означает:

- первая позиция — свободная;
- вторая позиция — `а`;
- третья позиция — свободная;
- четвёртая позиция — `н`;
- пятая позиция — свободная.

## 6. Построение фильтров

Для создания фильтра используется `FilterBuilderFactory`.

```python
factory = FilterBuilderFactory(
    cfg=cfg,
    lfm=lfm,
    log=log,
)

filter_model = factory.build_filter_model(
    is_interactive=False,
)
```

Фабрика выбирает один из двух builder-классов:

| Builder                   | Источник параметров                                                                                           |
| ------------------------- | ------------------------------------------------------------------------------------------------------------------------------- |
| `InputFilterBuilder`   | Интерактивный ввод в консоли                                                                           |
| `ReceivedFilterBuilder` | Внешняя модель: REST API или значения по умолчанию из файла конфигурации. |

### `InputFilterBuilder`

Builder консольного режима:

1. запрашивает длину слова;
2. получает исключенные символы;
3. получает обязательные символы;
4. получает позиционные ограничения;
5. запрашивает сохранение результата в файл;
6. запрашивает вывод результата в терминал.

Введённые символы:

- приводятся к нижнему регистру;
- очищаются от недопустимых символов;
- освобождаются от дубликатов;
- проверяются на соответствие длине слова.

### `ReceivedFilterBuilder`

Builder внешних параметров:

1. получает сборку внешних параметров;
2. проверяет длину позиционных фильтров;
3. дополняет короткие фильтры пустыми позициями или `+`;
4. удаляет исключенные символы из множества обязательных;
5. очищает от недопустимых символов позиционные ограничения .

Если число позиционных ограничений превышает длину слова, выбрасывается `ValueError`.

## 7. Алгоритм поиска

Поиск реализован в `SearchWordsService.search_words()`.

Для каждой строки словаря выполняется следующая проверка:

1. слово приводится к нижнему регистру;
2. проверяется длина;
3. проверяется наличие всех обязательных символов;
4. проверяется отсутствие запрещённых символов;
5. проверяются фиксированные позиции;
6. проверяются запрещённые символы на позициях;
7. слово добавляется в множество результатов.

Результат:

- не содержит дубликатов;
- отсортирован по алфавиту;
- представлен как `list[str]`.

Основная проверка позиционных ограничений выполняется методом:

```python
SearchWordsService._matches_position_constraints(...)
```

Для каждой позиции:

```python
if required and required != "+" and letter != required:
    return False

if letter in forbidden:
    return False
```

## 8. Формирование отчёта

`ApplicationService.ReportService.generate_report()` выполняет полный сценарий обработки:

1. получает конфигурацию и модель фильтра;
2. создаёт builder;
3. строит нормализованный фильтр;
4. запускает `SearchWordsService`;
5. форматирует найденные слова;
6. при необходимости выводит результат в терминал;
7. при необходимости сохраняет результат в файл.

Метод возвращает:

```python
tuple[str, int, Path | None]
```

Значения кортежа:

1. отформатированный текст результата;
2. количество найденных слов;
3. путь к файлу отчёта или `None`.

Если слова не найдены, файл не создаётся.

### Форматирование строк

Метод `_format_words_as_lines()` группирует слова по строкам.

Максимальная длина строки задаётся параметром:

```python
APP_REPORT_LINE_LIMIT
```

Значение по умолчанию — `70`.

### Файл отчёта

По умолчанию отчёт сохраняется в:

```text
report/Found words.txt
```

Каталог создаётся автоматически.

## 10. HTTP-поиск

Основной маршрут:

```text
GET /search-word/search-result
```

### Параметры запроса

| Параметр        | Тип                 | Обязательный | Описание                                            |
| ----------------------- | ---------------------- | ------------------------ | ----------------------------------------------------------- |
| `word length`        | `int`               | Да                     | Длина слова                                       |
| `included`           | `str`               | Нет                   | Обязательные символы                     |
| `excluded`           | `str`               | Нет                   | Исключенные символы                       |
| `fixed position`     | `str`               | Нет                   | Фиксированные позиции                   |
| `excluded position`  | `list[str]`         | Нет                   | Исключенные символы по позициям |
| `saving file`         | `Да` \| `Нет` | Нет                   | Сохранить ли результат в файл      |

Пример запроса:

```text
/search-word/search-result?word+length=5&included=аня&excluded=лт&fixed+position=+а+н+&saving+file=Нет
```

Пробелы в параметрах удаляются до построения модели `SearchQuery`.

### Формат ответа

Формат определяется заголовком `Accept`:

- `text/html` — HTML-страница;
- другой формат — `text/plain`;
- `saving file=Да` — файл `Found words.txt`.

При наличии результатов HTTP-статус равен `200`.

Если совпадения отсутствуют, возвращается `404`:

```text
Совпадений не обнаружено.
Количество найденных слов: 0
```

Если параметры имеют некорректные значения, возвращается `400`.

При выдаче файла количество найденных слов передаётся в заголовке:

```text
Quantity-Found-Words
```

## 15. Жизненный цикл веб-приложения

Веб-приложение использует `FastAPI` `lifespan`.

При запуске:

1. записывается сообщение в лог о старте веб-сервера;
2. при необходимости создаётся фоновая задача открытия браузера;
3. начинается обработка запросов.

При завершении:

1. записывается сообщение об остановке веб-сервера;
2. выполняется небольшая задержка для завершения фоновых операций.

Браузер автоматически открывается только вне Docker, если:

```text
APP_IS_OPEN_WEBBROWSER=true
```

# Bookmark Directory Analytics

Техническая документация проекта для анализа структуры закладок браузера.

Приложение работает с базой `places.sqlite`, используемой браузерами Firefox-совместимого семейства, и формирует текстовый отчёт по выбранной папке закладок. Поддерживаются консольный запуск, HTTP API на FastAPI и HTML-интерфейс.

## Требования

- Python `>=3.14`;
- [uv](https://github.com/astral-sh/uv);
- браузер Floorp или совместимый профиль с базой `places.sqlite`.

Зависимости проекта объявлены в `pyproject.toml`:

- `aiosqlite`;
- `fastapi[standard]`;
- `colorama`;
- `pyinstaller`.

## Установка

```bash
git clone https://github.com/VortexOwl/bookmark-directory-analytics.git
cd bookmarks-checker
uv sync
```

## Архитектура

Основные компоненты:

- `src/start.py` — точки входа консольных команд;
- `src/config.py` — конфигурация приложения и Uvicorn;
- `src/app/database.py` — копирование базы и работа с SQLite;
- `src/app/report.py` — сервисы формирования и очистки отчётов;
- `src/web/router.py` — FastAPI-приложение и HTTP-маршруты;
- `src/templates/` — HTML-шаблоны пользовательского интерфейса.
- `src/static/` —CSS-стили пользовательского интерфейса.

### Формирование отчёта

`ReportService.generate_report()` выполняет следующие операции:

1. Проверяет путь к исходной базе браузера.
2. Копирует `places.sqlite` в каталог `data`.
3. Открывает локальную копию базы через `aiosqlite`.
4. Ищет папку по полю `title` таблицы `moz_bookmarks`.
5. Подсчитывает закладки и дочерние папки.
6. Возвращает текст отчёта.
7. При `is_save_file=True` создаёт каталог отчётов и сохраняет файл.

Если путь к профилю не определён, используется ранее сохранённый файл базы в каталоге `data`, если он существует.

Анализ выполняется для исходной папки и её непосредственных дочерних папок. Более глубокие уровни вложенности не обходятся рекурсивно.

## Консольные команды

Команды объявлены в секции `[project.scripts]` файла `pyproject.toml`.

| Команда     | Точка входа     | Назначение                                                                                                |
| ------------------ | ------------------------- | ------------------------------------------------------------------------------------------------------------------- |
| `uv run start`   | `start:start_web`      | Запуск веб-сервера                                                                                  |
| `uv run default` | `start:start_default`  | Формирование и сохранение отчёта с конфигурацией по умолчанию |
| `uv run clear`   | `start:start_clear`    | Очистка каталога отчётов                                                                      |

### Формирование отчёта

```bash
uv run default
```

По умолчанию отчёт сохраняется в:

```text
report/Bookmarks KDE Store.txt
```

### Запуск веб-сервера

```bash
uv run start
```

По умолчанию сервер доступен по адресу:

```text
http://127.0.0.1:8000
```

Интерактивная документация FastAPI:

```text
http://127.0.0.1:8000/docs
```

### Очистка отчётов

```bash
uv run clear
```

Команда удаляет файлы из каталога, заданного параметром `report_folder`. По умолчанию используется каталог `report`.

## Конфигурация приложения

Класс `Config` находится в `src/config.py`. Переменные окружения используют префикс `APP_`.

| Параметр                  | Значение по умолчанию | Назначение                                             |
| --------------------------------- | ---------------------------------------- | ---------------------------------------------------------------- |
| `log_level`                    | `10`                                  | Уровень журналирования                      |
| `is_open_webbrowser`           | `True`                                | Открывать веб-интерфейс в браузере |
| `bookmarks_folder`             | `KDE Store`                           | Имя анализируемой папки                     |
| `browser`                      | `Floorp`                              | Имя браузера                                          |
| `browser_folder`               | `.floorp`                             | Каталог профилей браузера в Linux        |
| `custom_name_browser_profile`  | `None`                                | Имя профиля браузера                           |
| `custom_name_report_file`      | `None`                                | Пользовательское имя отчёта             |
| `database_file`                | `places.sqlite`                       | Имя файла базы данных                          |
| `data_folder`                  | `data`                                | Каталог локальной копии базы            |
| `report_folder`                | `report`                              | Каталог отчётов                                    |

### Производные пути

- `patch_data_folder` — путь к каталогу данных;
- `path_data_file` — `<data_folder>/<database_file>`;
- `path_report_folder` — путь к каталогу отчётов;
- `name_report_file` — пользовательское имя или `Bookmarks <bookmarks_folder>`;
- `path_report_file` — `<report_folder>/<name_report_file>.txt`;
- `path_browser_profile` — путь к профилю браузера;
- `path_source_database` — путь к исходной базе `places.sqlite`.

### Поиск профиля браузера

В Windows используется путь:

```text
%USERPROFILE%/AppData/Roaming/<browser>/Profiles/
```

В Linux используется:

```text
$HOME/<browser_folder>/
```

Если `custom_name_browser_profile` не задан, выбирается первый каталог, соответствующий шаблону:

```text
*.default*
```

Поддерживаются Windows и Linux. Для других операционных систем путь к профилю не определяется.

### Конфигурация Uvicorn

Класс `ServerConfig` использует префикс `SERVER_`.

| Параметр | Значение по умолчанию | Назначение                                  |
| ---------------- | ---------------------------------------- | ----------------------------------------------------- |
| `host`        | `127.0.0.1`                           | Адрес сервера                             |

```text
host=0.0.0.0

```

## HTTP API

### `GET /`

Перенаправляет на HTML-форму анализа:

```text
/directory-analytics/new
```

### `GET /directory-analytics/report`

Формирует отчёт по выбранной папке.

Query-параметры:

| Имя параметра | Обязательность | Значения                   |
| ------------------------- | ---------------------------- | ---------------------------------- |
| `saving file`          | обязательно       | `Да` или `Нет`      |
| `bookmarks folder`     | необязательно   | Имя папки закладок |

Пример:

```text
GET /directory-analytics/report?saving%20file=Нет&bookmarks%20folder=KDE%20Store
```

Поведение:

- `saving file=Нет` — возвращается `text/plain`;
- `saving file=Да` — отчёт сохраняется и возвращается как `FileResponse`;
- HTML-запросы получают HTML-страницу с результатом.

Коды ответов API:

- `200 OK` — отчёт сформирован;
- `400 Bad Request` — указанная папка отсутствует в базе;
- `404 Not Found` — база закладок не найдена.

Сообщение об отсутствии базы:

```text
По указанному пути отсутствует файл базы данных закладок.
```

При запуске в Docker сообщение дополнительно содержит указание разместить базу в примонтированном каталоге `data`.

### `POST /update-config`

Изменяет параметры конфигурации.

Поля `form-data`:

| Поле                     | Описание                                                                                                           |
| ---------------------------- | -------------------------------------------------------------------------------------------------------------------------- |
| `browser`                 | Браузер; доступно значение`Floorp`                                                               |
| `bookmarks folder`        | Имя папки закладок                                                                                         |
| `custom browser profile`  | Имя профиля браузера                                                                                     |
| `name report file`        | Имя файла отчёта без расширения                                                                 |
| `is default`              | `Да` — сбросить настройки, `Нет` — изменить переданные параметры |

Пустые значения не изменяют текущую конфигурацию.

Для API-запроса возвращается JSON:

```json
{
  "browser": "Floorp",
  "bookmarks_folder": null,
  "browser_profile": null,
  "custom_report_file": null,
  "is_default": "Нет"
}
```

HTML-запрос получает страницу подтверждения.

### `POST /cleanup`

Удаляет файлы из каталога `report_folder`.

API-ответ:

```json
{
  "status": "ok",
  "message": "Ручка очистки директории отчетов от файлов доступна через POST /cleanup",
  "report": {
    "success": 1,
    "errors": 0,
    "names of errors": []
  }
}
```

Если каталог отчётов отсутствует, операция завершается с нулевой статистикой удаления.

### `GET /shutdown`

Устанавливает флаг завершения Uvicorn-сервера.

Для обычного API-запроса возвращается:

```json
{
  "status": "ok",
  "message": "Запрос на остановку сервера отправлен"
}
```

HTTP-статус ответа — `202 Accepted`.

### HTML-маршруты

| Маршрут                     | Назначение                               |
| ---------------------------------- | -------------------------------------------------- |
| `GET /directory-analytics/new`  | Форма анализа закладок         |
| `GET /update-config`            | Форма настройки приложения |
| `GET /cleanup`                  | Форма очистки отчётов           |

## Формат отчёта

Пример:

```text
Initial catalog: KDE Store
bookmarks: 0
catalogs: 2
---------------------------------------------------------------------------------------------
Глобальные темы
bookmarks: 3
---------------------------------------------------------------------------------------------
Заставки
bookmarks: 1
```

В базе Firefox используются следующие типы записей:

- `type=1` — закладка;
- `type=2` — папка.

Считаются только непосредственные дочерние элементы текущей папки.
